# 1.1 도입 범위와 비기능 판정 기준

기준일: 2026-10-20 (Asia/Seoul). 상태: 회원가입 샘플·단일 VM의 우선 검증 범위는 사용자 확인 완료. 비기능 수치는 시험용 제안값으로 진행하며 운영 약정은 미확정. 운영 요구와 인수자 확정 전에는 WBS 1.1 및 G0를 완료로 처리하지 않는다.

## 사용자 결정 기록

2026-10-20 (Asia/Seoul) 사용자 답변을 반영했다.

- 우선 검증 업무/환경: **회원가입 샘플·단일 VM**.
- 운영 목표/인수자: **미정, 시험용 제안값으로 진행**.
- 적용 효과: 위 범위에서 개발·시험 준비를 계속한다. PostgreSQL 운영 채택, 실제 운영 SLO/복구·보존 약정, 담당자 확정 또는 G0 인수 승인을 의미하지 않는다.

## 적용 범위

첫 검증 업무는 기존 `MEMBER_SIGNUP`이다. 사용자 → Gateway → Member → HR → Member DB 경로의 성공·업무 거부·의존성 장애를 검증한다. Auth 로그인과 Trace 수집/조회, 테스트 UI는 연관 경로다. 휴면/외부 적격성은 현재 실제 연계가 없는 샘플 단계이므로 운영 기능 또는 실제 외부 호출 완료로 계산하지 않는다.

첫 적용은 비운영 검증 환경이다. 운영 적합성 인수는 실제 차세대 업무 1건, 합의한 부하, 보안 및 복구 시험을 통과한 버전에 한한다. Redis·Kafka·범용 워크플로 엔진·전사 서비스 확대는 제외한다.

| 구분 | 개발/시험 기준 | 운영 확정 여부 |
|---|---|---|
| 런타임 | Java 25, 저장소 고정 Gradle/Boot/Cloud 버전 | 개발 기준 반영, 조직 지원·라이선스 정책 별도 확인 |
| 배포 | 단일 VM에서 독립 프로세스, 별도 포트·검증 데이터 | 우선 검증 범위 사용자 확인; 실제 VM 사양·운영 망·HA 미확정 |
| DB | H2 독립 테스트 + PostgreSQL 18 임시 DB의 SQL/중단 복구 drill | 실제 DB/HA·앱 전체 PG 호환성은 WBS 4.1 |
| 업무 데이터 | HR 기존 ACTIVE/INACTIVE 샘플, 매 실행 신규 테스트 식별자 | 실제 업무/개인정보 사용 금지 |
| 수집 | 중요 업무 DB Outbox + HTTP, 기술 span 비동기 | 계약 명세 단계, 구현은 WBS 4.4 |
| 권한 | 외부 Gateway 진입, 내부 수집 서비스 인증, 운영 조회 RBAC | 구현/보안 시험은 WBS 3번 |

## 시험용 제안값

운영 약정이나 현재 달성값이 아니다. 현재 Gateway 오류가 복구되기 전 부하 성능을 판정하지 않는다.

| 항목 | 시험용 목표 제안 | 측정/판정 |
|---|---|---|
| 정상 대표 업무 부하 | 10 RPS 10분, 워밍업 2분 제외 | 정해진 데이터셋·동시 요청 수·호스트 자원 함께 기록 |
| 응답 지연 | 대표 정상 요청 p95 ≤ 1초 | Gateway 기준, 업무 거부/인위적 장애는 별도 집계 |
| 기술 오류율 | 정상 부하에서 1% 미만 | 5xx·연결 실패·Timeout 포함, 의도한 업무 거부 분리 |
| 호출 시간 예산 | HR 연결 0.5초, 응답 2초, 전체 요청 3초 | 구현은 4.6; Retry 전체도 총 deadline 내 포함 |
| 흐름 완전성 | 중요 업무 상태/종료 이력 100%, 수집 정상 시 5초 내 조회 | 원본 DB와 대조, 기술 span 유실은 별도 측정 |
| 계측 오버헤드 | 계측 전후 대표 부하 p95 증가 ≤ 5% | 동일 조건 반복 측정, 측정 노이즈·표본 수 기록 |
| 장애 관측 | probe 10초·timeout 2초·3회 실패, 미관측 30초 | 초기 UNKNOWN·대상 실패·수집 중단을 구분 |
| 복구 판단 | 2회 연속 성공 후 복구 | 실제 요청 지표·필수 인스턴스 수 함께 확인 |
| 복구 drill | RTO 30분, 업무 원본 DB RPO 15분 제안 | 백업/복원 실험 필요; 중요 이벤트는 원본 commit과 원자 저장 |
| 보존 | span/stack 14일, 업무/오류 90일, 집계 1년 제안 | 개인정보·법정 보존·용량 산정 후 확정 |
| 가용성 SLO | 미확정 | 월간 서비스 범위·계획정비·SLI·목표 비율 합의 필요 |

## 운영 요구 미확정 목록

| ID | 결정할 내용 | 결정 역할 | 현재 처리 |
|---|---|---|---|
| D01 | 차세대 실제 첫 업무·연계 대상·인수 범위 | 업무 책임자 | 우선 검증은 회원가입 샘플로 사용자 확정; 실제 업무 적용은 WBS 9.4에서 별도 확정 |
| D02 | 배포 플랫폼·서버 수·HA·인스턴스 발견·망 경계 | 운영/플랫폼 책임자 | 우선 검증은 단일 VM으로 사용자 확정; VM 사양·망·운영 HA는 후속 |
| D03 | peak RPS·동시 사용자·지연/가용성 SLO | 업무·운영 책임자 | 사용자 미정 회신; 시험용 제안값으로 진행, 운영 약정은 보류 |
| D04 | 운영 DB·백업·RTO/RPO·보존/개인정보 정책 | 운영·데이터/보안 책임자 | 임시 PG drill과 제안 정책 |
| D05 | 업무·운영·보안 인수자 및 담당 실명 | 프로젝트 책임자 | 역할만 정의, 임의 실명 배정하지 않음 |

확정값은 결정일·결정자·근거와 함께 기록하고 계약/시험의 변경 영향을 갱신한다. 미확정 사항은 운영 인수 G0를 막지만 로컬 설계·검증 도구 준비는 진행할 수 있다. 기존 WBS의 1.1 선행 조건은 사용자 확인한 우선 검증 범위와 시험용 제안값 내 작업을 허용하도록 한정하며 운영 선행 조건을 충족한 것으로 간주하지 않는다.
